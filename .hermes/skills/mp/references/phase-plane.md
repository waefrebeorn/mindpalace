# Extension phase plane

Two axes, not a to-do list. Move both deliberately — a capability is not real
at R2 just because it passes at D0.

- **Capability radius** R0 file → R1 module → R2 repo → R3 ecosystem.
- **Review depth** D0 shape → D1 negative control → D2 differential oracle →
  D3 cross-config/statistical → D4 formal proof.

| Phase | Radius | Depth | Exit condition |
|---|---|---|---|
| P0 Orient | R0-R1 | D0-D1 | every named path exists, claim falsifiable |
| P1 Attack | R1-R2 | D2 | old code fails the new gate |
| P2 Close | R2 | D2-D3 | narrow + full + product gates green |
| P3 Prestige | R2-R3 | D3 | fresh agent can continue from written state |

## Extension directions

- **skill depth**: add a skill only after the procedure survives one full loop;
  record author, version and trigger.
- **index depth**: the index must cover every file, including new skills; a
  dead path in any doc fails verification.
- **oracle depth**: prefer native/cross-toolchain oracles over self-checks.
- **prestige depth**: the next agent must verify, not merely trust.
- **automation depth**: make the palace queryable and scriptable via `commands/mp`.
